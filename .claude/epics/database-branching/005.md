# Storage Management

## Overview
Implement comprehensive storage management for database snapshots with metadata tracking, cleanup policies, and optimization. Provides efficient storage with intelligent retention and compression.

## Acceptance Criteria

### Core Storage Operations
- [ ] Local filesystem storage with atomic write operations
- [ ] Metadata tracking for snapshots (branch, timestamp, size, checksum)
- [ ] Branch ancestry tracking for fallback snapshot chains
- [ ] Compression optimization with configurable algorithms
- [ ] Storage path organization by project and branch structure

### Retention and Cleanup
- [ ] Automatic cleanup policies based on age, count, and storage limits
- [ ] Cleanup respects branch ancestry to maintain restore capability
- [ ] Manual cleanup commands with dry-run and selective options
- [ ] Storage usage monitoring and alerts
- [ ] Garbage collection for orphaned and corrupted snapshots

### Performance and Efficiency
- [ ] Incremental snapshots using delta compression
- [ ] Parallel compression and decompression operations
- [ ] Storage deduplication for identical database states
- [ ] Background cleanup operations without workflow interruption
- [ ] Storage integrity verification and repair

## Technical Details

### Storage Structure
```
.dbranching/
├── snapshots/
│   ├── main/
│   │   ├── snapshot-20250830-142252.db.gz
│   │   └── snapshot-20250830-142252.meta.json
│   └── feature-auth/
│       ├── snapshot-20250830-143015.db.gz
│       └── snapshot-20250830-143015.meta.json
├── metadata/
│   ├── index.db (SQLite tracking database)
│   └── config.yaml
└── temp/
    └── [atomic write operations]
```

### Metadata Schema
```json
{
  "snapshot_id": "uuid",
  "branch": "feature-auth",
  "parent_branch": "main",
  "timestamp": "2025-08-30T14:30:15Z",
  "database_name": "myapp_development",
  "size_compressed": 1024576,
  "size_uncompressed": 4096000,
  "checksum": "sha256:abc123...",
  "compression_algorithm": "gzip",
  "schema_version": "1.0",
  "git_commit": "a1b2c3d4",
  "restoration_tested": true
}
```

### Cleanup Policy Engine
- Age-based cleanup: Remove snapshots older than N days
- Count-based cleanup: Keep only M most recent per branch
- Size-based cleanup: Remove oldest when storage exceeds limit
- Ancestry-aware cleanup: Preserve fallback chains
- Custom retention rules per branch pattern

### Compression Strategy
- Configurable compression algorithms (gzip, lz4, zstd)
- Compression level tuning for speed vs space trade-off
- Detection of already compressed data to avoid double compression
- Parallel compression for large databases
- Streaming compression for memory efficiency

### Performance Optimization

- Disk usage monitoring and early warning
