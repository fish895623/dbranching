# Task 003: Snapshot Engine Core

## Overview
Implement the core snapshot engine that orchestrates database snapshot creation and restoration. This includes atomic operations, compression, metadata management, integrity validation, and performance optimization for large databases.

## Acceptance Criteria
1. **Atomic Operations**: Ensure snapshot create/restore operations are fully atomic with proper rollback on failure
2. **Compression System**: Implement gzip compression with configurable levels and integrity verification
3. **Metadata Management**: Create comprehensive snapshot metadata with JSON format and versioning
4. **Data Integrity**: Implement checksum validation and corruption detection for all snapshot components
5. **Performance Optimization**: Optimize for large databases with streaming operations and memory efficiency
6. **Rollback Capability**: Provide safe rollback mechanisms for failed operations with state restoration
7. **Progress Reporting**: Real-time progress reporting for long-running operations with ETA calculation

## Technical Details

### Snapshot Structure
```
snapshot_name/
├── metadata.json          # Snapshot metadata and checksums
├── schema.sql.gz         # Database schema dump (compressed)
├── data.sql.gz          # Database data dump (compressed)
├── large_objects.tar.gz  # Large objects (if present)
└── checksums.sha256     # File integrity checksums
```

### Core Engine Interface
```python
class SnapshotEngine:
    async def create_snapshot(
        self, 
        name: str, 
        options: SnapshotCreateOptions
    ) -> SnapshotResult:
        """Create atomic database snapshot with compression and validation"""
        
    async def restore_snapshot(
        self, 
        name: str, 
        options: SnapshotRestoreOptions
    ) -> RestoreResult:
        """Restore database from snapshot with atomic rollback on failure"""
        
    async def validate_snapshot(self, name: str) -> ValidationResult:
        """Validate snapshot integrity and compatibility"""
        
    async def get_snapshot_info(self, name: str) -> SnapshotInfo:
        """Get detailed snapshot metadata and statistics"""
```

### Atomic Operation Implementation
- Use filesystem-level atomic operations (rename vs copy)
- Implement transaction-like behavior for multi-step operations
- Create temporary directories for intermediate states
- Automatic cleanup on failure with proper exception handling
- Support for operation resumption after interruption

### Compression Strategy
- Configurable compression levels (1-9) with size/speed trade-offs
- Stream-based compression to handle large databases efficiently
- Parallel compression for multi-file operations
- Compression ratio reporting and optimization suggestions
- Support for different compression algorithms (future: lz4, zstd)

## Notes
This is the core engine that users will depend on for data safety. Correctness and reliability are more important than performance, though both are critical. The atomic operation guarantee is essential - users must never lose data due to a failed operation.

The engine should be designed to handle edge cases like disk space exhaustion, network interruptions, and database locks gracefully. Recovery from partial operations should be automatic where possible.
